# Этап 11. Деплоим проект

## Цель

Получить рабочую систему в интернете: сайт, Mini App и API на Vercel, данные и cron в Supabase.

Один GitHub-репозиторий, три проекта Vercel. Сначала база и код, потом API, потом сайт и Mini App, потом связка URL и Telegram. Следующий шаг нельзя закрывать, пока не открывается URL предыдущего.

`.env` в GitHub не коммитить. Секреты только в Vercel → Settings → Environment Variables. После любой `NEXT_PUBLIC_*` или `VITE_*` нужен Redeploy: эти значения попадают в сборку.

## 11.1. База в облаке

Уже сделано. Проект Supabase есть, строки лежат в `.env`: `DATABASE_URL` (порт `6543`, `pgbouncer=true`), `DIRECT_URL` (порт `5432`), `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`. Миграции применены, seed на месте: услуги, барберы, расписание, настройки.

На Vercel эти четыре переменные копируются из `.env` в Environment Variables. Сам файл `.env` в репозиторий не попадает.

- [x] Создать проект Supabase.
- [x] Взять `DATABASE_URL`: Transaction pooler, порт `6543`, в строке есть `pgbouncer=true`.
- [x] Взять `DIRECT_URL`: session / direct, порт `5432`. Prisma использует её для миграций.
- [x] Взять `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` (Project Settings → API).
- [x] Применить миграции к этой базе.
- [x] Прогнать seed.
- [x] В базе есть услуги, барберы, расписание и настройки.

## 11.2. Репозиторий

Три проекта Vercel подключаются к одному репозиторию. Корень — папка `barbershop`, не `apps/web`.

- [ ] Загрузить репозиторий в GitHub.
- [ ] Убедиться, что `.env` не попал в коммит.

## 11.3. Код, без которого Vercel не поднимется

Сейчас API запускается через `tsx src/index.ts` и `app.listen` на порту `3011`. Vercel так процесс не держит. Mini App в проде ходит на `/api` своего домена, а прокси Vite работает только локально.

- [ ] Отдать Fastify на Vercel как serverless-функцию, без `app.listen`.
- [ ] В сборке API вызывать `prisma generate` из корня репозитория. Схема лежит в `prisma/`, не в `apps/api`.
- [ ] Научить Mini App брать адрес API из `VITE_API_URL`.

## 11.4. Проект API

Сначала API: сайт и Mini App должны знать его URL.

- [ ] Создать Vercel project для `apps/api` из того же репозитория.
- [ ] Root Directory: `apps/api`.
- [ ] Включить Include source files outside of the Root Directory, иначе не видны `prisma/` и workspaces.
- [ ] Добавить `DATABASE_URL`, `DIRECT_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.
- [ ] Добавить `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET`, `CRON_SECRET`.
- [ ] `CORS_ORIGIN`, `APP_URL`, `MINIAPP_URL`, `TELEGRAM_WEBHOOK_URL` пока не заполнять.
- [ ] Дождаться URL вида `https://….vercel.app`.
- [ ] Открыть `/health` и убедиться, что API отвечает.

## 11.5. Проект сайта

Браузер ходит в API напрямую через `NEXT_PUBLIC_API_URL`. `API_PROXY_URL` нужен серверному прокси Next на `/api/v1`.

- [ ] Создать Vercel project для `apps/web`.
- [ ] Root Directory: `apps/web`, файлы вне корня тоже включить.
- [ ] `API_PROXY_URL` = URL API из шага 11.4, без слэша в конце.
- [ ] `NEXT_PUBLIC_API_URL` = тот же URL.
- [ ] Пересобрать проект после сохранения переменных.
- [ ] Открыть сайт и увидеть услуги и барберов из базы.

## 11.6. Проект Mini App

- [ ] Framework: Vite. Output Directory: `dist`. Root Directory: `apps/miniapp`.

## 11.7. Связать три URL

- [ ] Сделать Redeploy API.

## 11.8. Telegram

- [ ] В BotFather указать Mini App URL из шага 11.6.

- [ ] Отмена и перенос со страницы `/booking/[token]`.

- [ ] Mini App: запись, «Мои записи», отмена, перенос.
- [ ] Бот: подтверждение, отмена, перенос.
- [ ] Supabase Cron вызывает Edge Function `notifications`.
- [ ] Напоминание не отправляется повторно.
- [ ] Сайт и админка читаются с телефона.
- [ ] В репозитории нет `.env`, токенов и `SERVICE_ROLE_KEY`.
